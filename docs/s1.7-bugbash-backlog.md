## Item B — Inline edit persistence (bug)

`AdminReviewRequestsClient` holds `editPhone` and `editEmail` in local React state with no persistence path. There is no `PATCH /api/admin/review-requests/[id]` endpoint. Edits are lost on page refresh. The Send button uses `row.patient_phone` / `row.patient_email` from the loaded rows, not the local edit state — meaning a staff member can correct a phone number inline and still send to the old number. Silent data bug.

**Fix:** Add `PATCH /api/admin/review-requests/[id]` (contact fields only, no resend trigger). Auto-persist inline edits before send in `sendRow()` and `bulkSend()`.

AC: see original S1.6 spec D17-2 / D17-3 / AC-B1 through AC-B6.
