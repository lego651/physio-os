## 完整 intake-to-review pipeline (截至 2026-05-23 EOD)

1. Therapist 进 `/staff/intake` → Voice tab
2. STEP_1: 说 patient name → Whisper → Claude Haiku 清洗 → ASCII 守卫 → 幻觉黑名单 → bubble 显示
3. STEP_2: 说 treatment → extractTreatmentStep → {session_type, treatment_area} → bubble 显示 "service — area"
4. STEP_3: 说 therapist → Whisper → LLM fuzzy-match 11 个理疗师 → bubble canonical name → auto-advance
5. STEP_4: 说 notes → 长文本进 result
6. CONFIRM screen: 显示所有字段 + 调 match-patient API → 候选列表 (LLM 过滤相似度) → therapist 选 radio
7. Save:
   - 选 existing patient → INSERT intake_records (with patient_id + canonical name) + INSERT review_requests (phone/email auto-fill, channel auto-pick)
   - 选 "Save without patient" → INSERT intake_records (no patient_id, Whisper name) + INSERT review_requests (no contact, channel='email', status='pending')
8. Admin 进 `/dashboard/review-requests`:
   - 有 contact 的行: 直接 Send → 真实发送 (email via Resend / SMS via Twilio)
   - pending 行: 手填 phone/email → Send

## Lessons Learned

1. Prod DB 从未跑过 `supabase db push` — 任何新项目都要先建 migration baseline，不要假设 prod schema 和 local 一致。
2. Whisper `language='en'` 是 hint 不是约束 — 输出仍可能含中文。必须加服务端 script 守卫。
3. Clinic slug ≠ clinic UUID — API 一定要在服务端做 slug→UUID lookup，不信任 client 传的 ID 格式。
4. "永远 INSERT review_requests" 原则: intake 的价值在于触达机会，不能因为缺 contact 就不建行。前台补填比 therapist 发现漏了更好。
5. Jason 习惯边做边发现 bug，bug chain 会很长。保持 commit 粒度细，每个 bug 一个 commit，review 时清晰。
